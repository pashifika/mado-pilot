# MadoPilot v0.3.1

MadoPilot v0.3.1 adds an explicit non-default bounded ONNX OCR profile, one-to-eight caller-owned grouped zones, and initialization-time OCR provider policy through Rust, C ABI 1.5, and the header-only C++ wrapper. The grouped operation maps one checked source envelope, runs one detector scan, recognizes each selected detection once, and publishes immutable caller-order groups atomically.

This file is the canonical release body. The release candidate is not published: final review and protected checks, the `dev/0.3.1` to `main` release PR, exact-main checks, and the permanent annotated tag remain required. Focused or hosted evidence does not substitute for that release boundary.

## Explicit bounded profile

The profile identity is `phase-3-1-rapidocr-ppocrv4-det-v6-rec-small-bounded-v2`, with preprocessing `rapidocr-ppocrv4-det-bgr-db736-fit-1312x736-then-tensor6291456b-linear-half-pixel-source-rec-v2`.

It reuses the released G-004 component bytes:

- RapidOCR v3.9.2 `ch_PP-OCRv4_det_mobile.onnx`, 4,745,517 bytes, SHA-256 `d2a7720d45a54257208b1e13e36a8479894cb74155a5efe29462512d42f49da9`;
- RapidOCR v3.9.2 `PP-OCRv6_rec_small.onnx`, 21,234,383 bytes, SHA-256 `6f327246b50388f3c176ae304bd95767ea6dc0c9ae92153ef8cbe210b3c14884`;
- 18,708-entry vocabulary, SHA-256 `f7aa897ca828a4c7c9e2739c30f9161a33306d532f020bcdb91dcfb664a5507e`; and
- ONNX Runtime 1.29.0, C API 17; every existing constructor remains built-in CPU only.

The detector first fits a nonzero 32-aligned rectangle no larger than 1312×736. Oversized desired work then receives a second aspect-preserving fit so the detector tensor remains at most 6,291,456 bytes. Reference-size and odd-size inputs retain the 1312×736 detector and the absolute profile tensor bound remains 11,587,584 bytes. Recognition crops always read the original mapped source, not the resized detector image.

Callers select this profile explicitly and supply canonical absolute model-root and runtime paths. Existing constructors remain unchanged: constructors without OCR still omit it, and `*_engine_with_default_ocr` still selects released native G-004. Missing prerequisites, identity mismatch, cancellation, or deadline failure publishes no engine and triggers no fallback, search, download, retry, or alternate profile.

## One-to-eight grouped zones

A grouped request contains one to eight capture-pixel rectangles in caller order. MadoPilot resolves every zone first, computes the smallest checked source envelope, maps it once, invokes the backend once, and assigns each normalized candidate by its source centroid under exact half-open rectangle semantics.

Successful results expose:

- complete source-frame identity and the shared source envelope;
- the selected backend, model, version, profile, and preprocessing identities;
- each effective zone in caller order, including explicit empty groups;
- global detector order within every group;
- unique text, geometry, and confidence storage with compact group memberships; and
- immutable ownership independent of request storage, frame, package, session, engine, mapping, tensor, backend buffer, model source, or session guard.

The release support boundary is limited to the qualified non-overlapping layouts: one full-frame zone equivalent to singular bounded OCR, three semantically distinct sparse zones, and eight separated HUD zones. Duplicate, one-pixel-different, adjacent, slight-overlap, and complete-overlap arrays remain structurally admitted safety cases only. Callers own their semantic meaning. MadoPilot preserves every rectangle, computes ordinary deterministic membership, and makes no independent-quality, deduplication, reconciliation, or latency claim for those layouts.

Hard operation-wide limits are one to eight zones, at most 1,000 raw and unique candidates, at most 8,000 memberships, raw text at most 16 KiB per candidate and 16,384,000 bytes aggregate, normalized text at most 4 KiB per candidate and 4,096,000 bytes aggregate, source mapping at most 268,435,456 bytes, grouped temporary semantic storage at most 262,144 bytes, membership indexes at most 16,000 bytes, and immutable grouped semantic storage at most 5,242,880 bytes. Checked over-limit, malformed, interrupted, or closing operations publish no partial result.

## Public surfaces and compatibility

- The workspace and Cargo package version is `0.3.1`.
- Rust callers construct `OcrProfileConfig` for the explicit CPU bounded profile or `OcrProviderConfig` for independent model/provider selection, then inspect `Engine::ocr_provider`.
- C callers negotiate ABI minor 5. Provider construction uses the 32-byte `madopilot_ocr_provider_options_t`; provider observation uses the 40-byte engine-owned descriptor.
- C++ callers use owning `OcrProfileOptions`, `OcrProviderOptions`, and `ZoneScanOcrRequest` values. Their projections rebind after copy, move, assignment, and vector relocation. Provider and OCR descriptor accessors are lvalue-only.
- Existing constructors and ABI 1.0–1.4 entries remain CPU-only and behavior-compatible.
- ABI 1.0, 1.2, 1.3, and 1.4 remain permanent 424-byte, 592-byte, 648-byte, and 720-byte prefixes. ABI 1.5 appends provider construction at offset 720 and descriptor access at offset 728 for a complete 736-byte table.
- The unreleased ABI 1.1 draft remains unsupported. Recompile against a released header; do not copy draft numeric values or layouts.

The production examples are:

```text
crates/mado-pilot/examples/ocr-profile-zones.rs
crates/bindings/capi/examples/c/ocr-profile-zones.c
crates/bindings/capi/examples/cpp/ocr-profile-zones.cpp
```

The independent CMake consumer compiles the C and C++ surfaces directly from the development tree. No CMake install/export set exists.

## Provider policy and target decisions

Provider policy is independent from native/bounded preprocessing:

- `Cpu` and every existing constructor use the released CPU path;
- `PreferCuda`/`PreferCoreMl` may construct a fresh CPU pair only after
  pre-publication provider initialization failure;
- `RequireCuda`/`RequireCoreMl` return a typed failure and no engine; and
- a published engine never retries inference on CPU, mixes detector/recognizer
  providers, or switches provider after cancellation/device/native failure.

Engine descriptors report requested policy, active provider, initialization
fallback and its bounded reason, and runtime-profile identity without retaining
caller paths or native provider storage. The released diagnostic stream remains
unchanged; required failure publishes no engine or diagnostic reader.

ADR 0047 rejects CoreML support after mixed CoreML/CPU placement succeeded but
two fixed workloads failed geometry and active cancellation exceeded its bound.
Preferred CoreML reports `QualificationRejected` and fresh CPU; required CoreML
fails.

the exact successor source tree
`896e037d962610c4abd7a4a7b143d1ae9c90f549` on the same controlled Windows
boundary. CUDA recognizer submissions now have an internal 128 MiB output bound:
ordinary accepted widths retain batches of six, while six maximum-width
candidates split into `[3, 3]`. Public limits and APIs are unchanged.

## Prerequisites and development-tree examples

The caller supplies one canonical absolute runtime file: `libonnxruntime.1.29.0.dylib` on Apple Silicon or `onnxruntime.dll` on Windows. The model root contains exactly:

```text
rapidocr-v3.9.2/ch_PP-OCRv4_det_mobile.onnx
rapidocr-v3.9.2/PP-OCRv6_rec_small.onnx
```

Environment variables below pass reviewed paths only into the examples; the library itself performs no environment lookup:

```sh
export MADO_PILOT_G004_MODEL_ROOT=/canonical/model/root
export MADO_PILOT_ONNX_RUNTIME=/canonical/path/libonnxruntime.1.29.0.dylib
cargo run --locked --package mado-pilot --example ocr-profile-zones
cargo build --locked --package mado-pilot-capi
cargo run --locked --package mado-pilot-capi --example c-abi-check -- --label "<host>"
```

On Windows, CPU uses the controlled CPU runtime. Explicit CUDA requires the version-matched GPU `onnxruntime.dll` and provider/dependency DLLs in one canonical root; the source release supplies none. The ABI checker compiles and runs current C/C++/CMake consumers plus immutable ABI 1.0/1.2/1.3/1.4 callers.

## Troubleshooting

- `ONNX runtime path is not the controlled canonical target file` (`InvalidArgument`): the runtime path is relative, non-canonical, or names the wrong target file.
- `controlled ONNX runtime is unavailable`, `... incompatible`, or `a conflicting ONNX runtime is already initialized` (`Unsupported`): the file cannot be loaded with the restricted flags, does not report 1.29.0/API 17, or another process-global runtime won initialization.
- `accepted OCR model root is not an absolute directory` (`InvalidArgument`) or `... is unavailable` (`Unsupported`): the selected root is invalid or cannot be opened.
- `accepted OCR detector/recognizer is unavailable at <fixed relative path>` (`Unsupported`) or `must be <length> bytes with SHA-256 <expected digest>` (`AssetInvalid`): a fixed component is missing, not regular, or mismatched.
- `OCR graph metadata does not match the selected profile` (`InvalidArgument`): model graph or vocabulary metadata is incompatible.
- `requested ONNX execution provider failed release qualification` (`Unsupported`): CoreML was explicitly preferred or required after ADR 0047 rejected its release row. Preferred policy may publish fresh CPU with `QualificationRejected`; required publishes no engine.
- `controlled ONNX provider dependency is unavailable` (`Unsupported`): a CUDA root is absent, non-canonical, not colocated with the selected runtime, or misses/mismatches a required regular file. Preferred CUDA may publish fresh CPU; required CUDA fails.
- `ONNX execution provider initialization failed` (`VisionFailed`): registration or detector/recognizer session creation failed. Fallback remains initialization-only and is visible in a successful engine descriptor.
- `ONNX backend resource ceiling would be exceeded` (`LimitExceeded`): detector dimensions, tensor/output bytes, candidate/text/storage counts, or grouped memberships exceed a checked profile bound.
- `ONNX backend inference slot is occupied` (`LimitExceeded`): the profile admits one synchronous inference and does not queue concurrent work.
- `operation was cancelled` or `operation deadline passed`: no late result is published. Cancellation after native admission issues bounded best-effort termination and the backend remains reusable unless close became authoritative.
- A grouped accessor index equal to the zone or region count is invalid. Empty groups are successful values with zero regions, not missing groups.
- macOS Screen Recording and event-post access remain separate non-prompting native capabilities. OCR over replay frames requires neither and never requests permission.

Errors and ordinary diagnostics exclude caller-selected absolute model/runtime/provider paths, model bytes, pixels or captured-content hashes, recognized text, caller zone arrays, credentials, raw native identifiers, process inventories, and unrelated desktop metadata. Engine-owned provider descriptors expose only bounded policy/provider/fallback/runtime-profile facts. The released diagnostic stream is unchanged and `Off` creates no queue or diagnostic allocation.

## Distribution scope and unavailable artifacts

This release remains a developer-facing source runtime. It publishes source archives only. It provides no crates.io packages, prebuilt libraries, installer, package-manager formula, CMake install/export set, pkg-config file, static library, ABI-major decorated loader artifact, OpenCV, ONNX Runtime, or model file.

It does not provide visual-condition watchers, wait-for-text, OCR scheduling/coalescing, callbacks, per-inference retry/provider switching, automatic input, bundled GPU/runtime dependencies, packaging downloads, arbitrary profile selection, arbitrary-application zone qualification, a GUI, tray, overlay, editor, updater, workflow catalog, general scripting DSL, or time-based scheduler.

Publication requires exact final-main repository-policy, Windows, and Apple Silicon checks; a permanent annotated `v0.3.1` tag; provider release notes equal to this tracked body; and verified source archives and URL. Hosted correctness smoke supports but never replaces approved Windows desktop and Apple Silicon quality/performance evidence.
