# MadoPilot v0.3.1

MadoPilot v0.3.1 adds an explicit non-default bounded ONNX CPU OCR profile and one-to-eight caller-owned grouped zones through Rust, C ABI 1.4, and the header-only C++ wrapper. The grouped operation maps one checked source envelope, runs one detector scan, recognizes each selected detection once, and publishes immutable caller-order groups atomically.

This file is the canonical release body. The release candidate is not published: final review and protected checks, the `dev/0.3.1` to `main` release PR, exact-main checks, and the permanent annotated tag remain required. Focused or hosted evidence does not substitute for that release boundary.

## Explicit bounded profile

The profile identity is `phase-3-1-rapidocr-ppocrv4-det-v6-rec-small-bounded-v2`, with preprocessing `rapidocr-ppocrv4-det-bgr-db736-fit-1312x736-then-tensor6291456b-linear-half-pixel-source-rec-v2`.

It reuses the released G-004 component bytes:

- RapidOCR v3.9.2 `ch_PP-OCRv4_det_mobile.onnx`, 4,745,517 bytes, SHA-256 `d2a7720d45a54257208b1e13e36a8479894cb74155a5efe29462512d42f49da9`;
- RapidOCR v3.9.2 `PP-OCRv6_rec_small.onnx`, 21,234,383 bytes, SHA-256 `6f327246b50388f3c176ae304bd95767ea6dc0c9ae92153ef8cbe210b3c14884`;
- 18,708-entry vocabulary, SHA-256 `f7aa897ca828a4c7c9e2739c30f9161a33306d532f020bcdb91dcfb664a5507e`; and
- ONNX Runtime 1.29.0, C API 17, built-in CPU provider only.

The detector first fits a nonzero 32-aligned rectangle no larger than 1312×736. Oversized desired work then receives a second aspect-preserving fit so the detector tensor remains at most 6,291,456 bytes. Reference-size and odd-size inputs retain the 1312×736 detector and the absolute profile tensor bound remains 11,587,584 bytes. Recognition crops always read the original mapped source, not the resized detector image.

Callers select this profile explicitly and supply canonical absolute model-root and runtime paths. Existing constructors remain unchanged: constructors without OCR still omit it, and `*_engine_with_default_ocr` still selects released native G-004. Missing prerequisites, identity mismatch, cancellation, or deadline failure publishes no engine and triggers no fallback, search, download, retry, or alternate profile.

## One-to-eight grouped zones

A grouped request contains one to eight capture-pixel rectangles in caller order. MadoPilot resolves every zone first, computes the smallest checked source envelope, maps it once, invokes the backend once, and assigns each normalized candidate by its source centroid under exact half-open rectangle semantics.

Successful results expose:

- complete source-frame identity and the shared source envelope;
- the selected backend, model, version, profile, and preprocessing identities;
- each effective zone in caller order, including explicit empty groups;
- global detector order within every group;
- unique text, geometry, and confidence storage with compact group memberships; and
- immutable ownership independent of request storage, frame, package, session, engine, mapping, tensor, backend buffer, model source, or session guard.

The release support boundary is limited to the qualified non-overlapping layouts: one full-frame zone equivalent to singular bounded OCR, three semantically distinct sparse zones, and eight separated HUD zones. Duplicate, one-pixel-different, adjacent, slight-overlap, and complete-overlap arrays remain structurally admitted safety cases only. Callers own their semantic meaning. MadoPilot preserves every rectangle, computes ordinary deterministic membership, and makes no independent-quality, deduplication, reconciliation, or latency claim for those layouts.

Hard operation-wide limits are one to eight zones, at most 1,000 raw and unique candidates, at most 8,000 memberships, raw text at most 16 KiB per candidate and 16,384,000 bytes aggregate, normalized text at most 4 KiB per candidate and 4,096,000 bytes aggregate, source mapping at most 268,435,456 bytes, grouped temporary semantic storage at most 262,144 bytes, membership indexes at most 16,000 bytes, and immutable grouped semantic storage at most 5,242,880 bytes. Checked over-limit, malformed, interrupted, or closing operations publish no partial result.

## Public surfaces and compatibility

- The workspace and Cargo package version is `0.3.1`.
- Rust callers construct `OcrProfileOptions`, choose `OcrProfile::BoundedDetector`, use a target-specific `*_engine_with_ocr_profile` constructor, and call `Session::scan_ocr_zones` with `ZoneScanOcrRequest`.
- C callers negotiate ABI minor 4 and the complete entry extent required by their operation, use `madopilot_ocr_profile_options_t` and `madopilot_ocr_zone_scan_request_t`, and own `madopilot_ocr_zone_scan_result_t` through retain/release.
- C++ callers use owning `OcrProfileOptions` and `ZoneScanOcrRequest` values. Their projections rebind after copy, move, assignment, and vector relocation. `ZoneScanOcrResult` is move-only; `clone()` is the only refcounting copy, and borrowed views are lvalue-only.
- The new engine OCR descriptor reports the selected backend/model/profile tuple. Engines without OCR return typed unsupported status with an initialized empty descriptor.
- ABI 1.0, 1.2, and complete 1.3 remain permanent 424-byte, 592-byte, and 648-byte prefixes. ABI 1.4 appends profile construction, grouped ownership/accessors, and the engine descriptor at offsets 648 through 712 for a complete 720-byte table. Existing 1.0/1.2/1.3 callers require no source change.
- The unreleased ABI 1.1 draft remains unsupported. Recompile against a released header; do not copy draft numeric values or layouts.

The production examples are:

```text

crates/bindings/capi/examples/c/ocr-profile-zones.c
crates/bindings/capi/examples/cpp/ocr-profile-zones.cpp
```

The independent CMake consumer compiles the C and C++ surfaces directly from the development tree. No CMake install/export set exists.

## Troubleshooting

- `ONNX runtime path is not the controlled canonical target file` (`InvalidArgument`): the runtime path is relative, non-canonical, or names the wrong target file.
- `controlled ONNX runtime is unavailable`, `... incompatible`, or `a conflicting ONNX runtime is already initialized` (`Unsupported`): the file cannot be loaded with the restricted flags, does not report 1.29.0/API 17, or another process-global runtime won initialization.
- `accepted OCR model root is not an absolute directory` (`InvalidArgument`) or `... is unavailable` (`Unsupported`): the selected root is invalid or cannot be opened.
- `accepted OCR detector/recognizer is unavailable at <fixed relative path>` (`Unsupported`) or `must be <length> bytes with SHA-256 <expected digest>` (`AssetInvalid`): a fixed component is missing, not regular, or mismatched.
- `OCR graph metadata does not match the selected profile` (`InvalidArgument`): model graph or vocabulary metadata is incompatible.
- `ONNX backend resource ceiling would be exceeded` (`LimitExceeded`): detector dimensions, tensor/output bytes, candidate/text/storage counts, or grouped memberships exceed a checked profile bound.
- `ONNX backend inference slot is occupied` (`LimitExceeded`): the profile admits one synchronous inference and does not queue concurrent work.
- `operation was cancelled` or `operation deadline passed`: no late result is published. Cancellation after native admission issues bounded best-effort termination and the backend remains reusable unless close became authoritative.
- A grouped accessor index equal to the zone or region count is invalid. Empty groups are successful values with zero regions, not missing groups.
- macOS Screen Recording and event-post access remain separate non-prompting native capabilities. OCR over replay frames requires neither and never requests permission.

Errors and ordinary diagnostics exclude caller-selected absolute model/runtime paths, model bytes, pixels or captured-content hashes, recognized text, caller zone arrays, credentials, raw native identifiers, process inventories, and unrelated desktop metadata. Enabled grouped diagnostics carry only exact source identity, shared envelope, bounded aggregate counts, request-scoped work where authoritative, opaque model-instance correlation, profile classification, typed outcome, and exact loss counts. `Off` creates no queue and performs no diagnostic allocation.
