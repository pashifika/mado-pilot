# MadoPilot v0.5.0

MadoPilot v0.5.0 adds Rust OCR text-presence queries, selectable OCR model
profiles, sixteen-zone grouped OCR, native capture pacing, retained native window
requirements and target process provenance, an opt-in macOS AppKit background
pointer mode and direct RGBA/BGRA template matching. It retires the official C++
wrapper in favour of direct C ABI consumption and introduces developer-owned
native setup. The new capture, window, pointer and OCR-query APIs are Rust-only;
C ABI version 1.5, its entries and its layouts are unchanged.

This file is the canonical release body. Each section separates implemented
behavior from revision-bound verification. No hosted, development, diagnostic or
historical result below is promoted to native or performance qualification of
the final source.

## Release targets and verification authority

The release targets are unchanged:

- `x86_64-pc-windows-msvc`: Windows 11 and later serviced x64 desktop releases;
  deployment floor Windows 11 25H2 build family 26200.
- `aarch64-apple-darwin`: Apple Silicon macOS; deployment floor 26.5.2.
  macOS 27.0.1 has scoped CPU OCR and native-shim ASan verification, not complete
  capture/input topology qualification.

Release acceptance requires the repository-policy, Windows and Apple Silicon
checks on the exact final source. The hosted native jobs cover workspace build,
lint, tests, doctests and documentation, the direct C/C++ samples, ABI 1.5 and
frozen ABI 1.0/1.2/1.3/1.4 callers, the external Rust consumer and the
template-watch Lane A semantic run. They have no Screen Recording grant,
approved display topology or interactive input authority.

Native capture, input, watcher and OCR results cited below remain bound to their
recorded revisions and hosts. Current CPU OCR verification uses Apple M1 Pro
macOS 27.0.1 ([ADR 0081](../adr/0081-current-apple-ocr-verification-cohort.md))
and Core i7-12700KF Windows 11 Pro 26H2 build family 26300
([ADR 0082](../adr/0082-current-windows-ocr-reference-precursor.md)). Historical
platform qualification remains bound to macOS 26.6.2 (25G83) and Windows 11 25H2
build family 26200. No final-source native capture or input requalification on
those historical hosts is claimed.

The current macOS 27.0.1 host passed all 321 native-shim ASan library tests at
product source `1e4d0b4`, with no failed, ignored or filtered tests and an unchanged
executable hash. Missing display capture fails rather than skips; window-subject,
multi-display/mixed-scale seam, non-Retina and idle-producer note-and-pass branches
were not established. Runtime and clang/CLT identities were not hash-bound.
[ADR 0101](../adr/0101-current-apple-native-sanitizer-host.md) adopts this host for
new ASan runs only; manual input, topology and watcher gates remain separate.

## Rust template matching

- Preserve accepted RGBA8 and BGRA8 source layouts through matching, then convert
  directly to owned three-channel BGR. BGRA8 remains the default; alpha, scores,
  suppression and caller result limits are unchanged. ROI copies and native
  CPU readback remain.
- Reuse compatible live crop/channel-conversion mappings without retaining their
  source frames or extending CPU-copy reservations past the last pixel owner.
- Share bounded immutable BGR preparation across backend clones: two entries,
  33,554,432 retained payload bytes. Equal-stamp frames, mapping layouts and
  effective regions remain isolated; template results and operation authority
  remain independent.
- Select canonical candidates directly from request-owned scores, using a
  single-result scan or a row-bounded heap instead of a copied dense map and
  repeated whole-map scans. Dominated scores bypass normalization.
  Live winners stay in the heap until their row needs repair, avoiding redundant
  removal/reinsertion. `KeepAll` reserves result capacity from eligible rows and
  the caller's limit, reducing repeated growth; no-hit and overlap selection keep
  their existing allocation paths. Stop each scan at its first finite public
  maximum (`1.0`), preserving canonical ties while skipping the remaining offsets.
  Visited-prefix accounting, bounded checks and final caller authority remain;
  exact checkpoint positions can change.

`BackendDescriptor` adds `with_alternate_format` and `accepts_format`.
Existing constructors remain single-format; `format()` names the default, not
every actual mapping. Same-instance checks isolate independent equal-stamp
frames. Direct RGBA makes existing `ExactRgba` unchanged admission eligible,
without granting unchanged pixels stability-confirmation authority.

`match-report` replaces `pixelFormat` with `defaultPixelFormat` and
`acceptedPixelFormats`. Historical reports remain unchanged. These matching
changes preserve existing Rust signatures and facade exports; they do not change
the C ABI, OCR, scheduling policies, capture adapters or input delivery.
These changes do not declare target-specific performance qualification.

## Native capture pacing and terminal publication

- Rust callers select native capture pacing with `CapturePacingRequest` on the
  common engine request, the selected `WindowsConfig`/`MacosConfig` block or one
  `OpenRequest`. Resolution is session, OS block, common engine, then source
  default; the interval and required/preferred policy never merge across layers.
  `source_default()` leaves native cadence untouched and does not mean unlimited
  frame rate.
- After open, `session.description().capture_pacing()` reports `SourceDefault`,
  `Applied` with the configured interval, or `PreferredUnapplied` with a
  `PacingUnsupportedReason`. Required pacing that cannot be applied returns
  `Unsupported`. Replay and controlled capture refuse required pacing and report
  preferred pacing as unapplied.
- The model-free `completion-paced-ocr --controlled-smoke` example waits a full
  cooldown after OCR and caller interpretation, without capture or input.
  Separately authorized owned-fixture semantics and five comparison cases passed
  for native binaries at `2db68d0` on Windows 11 Pro 25H2 build `26200.9445` and
  macOS 26.6.2 (25G83). They are single predeclared cohorts, not general
  application performance guarantees or OS-floor qualification.
- Singular/grouped OCR and template search commit their exact retained frame
  through a capture commitment boundary ordered against the first capture-terminal
  fault and explicit close. A recorded target-loss fault is preserved rather than
  reported as ordinary closure. Commitment does not prove continued target
  readiness, permission or completed native cleanup. C and C++ calls inherit the
  runtime ordering without ABI change.

See [capture pacing](../capture-pacing.md),
[ADR 0077](../adr/0077-native-capture-pacing-and-completion-cooldown.md) and
[ADR 0078](../adr/0078-capture-terminal-publication.md).

## Retained native windows and process provenance

- `TargetDescription::window` describes a native window through a descriptive
  `NativeWindowId` and `WindowGeometry`: capture area, signed desktop origin,
  pixel extent and scales. A native window key is not transferable authority.
- `Engine::describe_window` revalidates the original retained target, process
  lifetime and window without capture or input. Neither adapter reconstructs
  authority from a process identifier, title or numeric window key.
- `OpenRequest::require_window_geometry` refuses changed geometry before opening
  and publishing. `OpenRequest::with_resource_limits` applies nonzero
  `CaptureResourceLimits` to one frame and to simultaneous session-retained image
  payload. Both are requirements: replay, controlled and unsupporting custom
  providers return `UnsupportedOption`. Byte accounting covers declared payload,
  detached storage, staging/CPU copies and observable padding, not GPU/driver
  allocation or RSS. Unverifiable Windows capture eligibility returns
  `UnsupportedOption`; known protection returns `AccessDenied`. Omitted options
  keep their previous behavior.
- A target description can expose `TargetProcessIdentity` when its provider
  retains the owning process lifetime: process identifier, opaque lifetime,
  absolute executable path and optional application-bundle path. It is a
  discovery snapshot, not continuing liveness or authorization. Debug output
  redacts it; its explicit path getters return machine-local data. Missing
  metadata leaves capture support unchanged.

Retained observations do not guarantee continued target readiness or replace
separate native qualification. See
[ADR 0079](../adr/0079-retained-native-window-requirements.md).

## macOS process-directed pointer input

- `MacosConfig::with_process_pointer_mode(MacosProcessPointerMode::AppKitBackground)`
  explicitly selects AppKit-backed construction for process-directed pointer
  movement and buttons; `CoreGraphics` remains the default. The opt-in mode ORs
  Command into each pointer event without posting a Command key, which can change
  an application's click or drag semantics. It refuses ordinary pointer input
  when construction capability or the background state is unavailable, or when
  the target is observed frontmost, without route fallback. System, keyboard,
  text and scroll construction are unchanged.
- The historical controlled matrices do not qualify this mode, arbitrary
  applications or games, concurrent typing or macOS 27. One revision-bound
  consumer workflow passed at `acc5d98`; see the
  [macOS input guide](../macos-input-verification.md#revision-bound-consumer-observation).
- Pressed buttons and keys belong only to the sequence that pressed or possibly
  pressed them. A partial stop releases them newest first within an independent
  cleanup bound of at most 256 releases and no new release after 250 ms. Moves
  that may have taken effect retain their destination for owned-button cleanup;
  cleanup does not prove where the application observed the pointer.

## OCR model choices

- `ocr_profiles()`, `ocr_profile(id)` and `OcrProfileConfig::from_id` expose the
  three implemented catalog profiles as ordinary Rust choices without opening
  models or loading ONNX Runtime: the unchanged native G-004 default
  (`DEFAULT_OCR_PROFILE_ID`), the explicit bounded-v2 profile and
  `ppocrv6-tiny-det-small-rec-max736-v1`, an ordinary CPU choice. Persist the
  profile ID, not a display name.
- Each profile carries target- and provider-scoped rule outcomes: `Passed`,
  `Failed`, `NotRun` or `Incomplete`. There is no aggregate rating. Failed or
  missing quality/performance results do not hide a choice, require an
  experimental opt-in, change the default or trigger fallback.
  `ppocrv6-tiny-det-small-rec-max736-v1` has recorded text and negative-image
  failures; it is not a promise of accuracy on the caller's images.
- Construction keeps technical validation: resource hashes and containment,
  graph/vocabulary consistency, finite execution bounds, source correlation,
  deadlines and owned cleanup. Package manifest v1/v2 cannot express the
  PP-OCRv6 auxiliary vocabulary resource and refuses that profile. Provider
  capabilities and the C/C++ surface are unchanged. Resources are caller-supplied,
  never distributed or fetched.
- Detector sigmoid maps admit finite values from zero through the next `f32` above
  one, preserving measured CPU roundoff. Larger, negative and nonfinite values
  remain malformed output. The detector input tensor is released after detection,
  before recognition crops are prepared; this does not change inference results
  or bound ONNX Runtime's internal allocations.

See the [OCR model catalog](../ocr-model-catalog.md),
[ADR 0080](../adr/0080-ocr-model-catalog-and-admission.md),
[ADR 0084](../adr/0084-ocr-model-choices-and-test-results.md) and
[ADR 0085](../adr/0085-detector-sigmoid-roundoff.md).

## OCR grouped scans

- Accept one through sixteen caller-order zones through Rust, C and C++.
  Zero or seventeen-or-more zones fail before mapping or backend work.
- Keep one shared source envelope and one detector invocation. The whole scan
  still permits at most 1,000 candidates; text, mapping, temporary and result-byte
  ceilings are unchanged. Only derived membership storage grows to 16,000
  references and 32,000 index bytes.
- `candidate_interest_membership` returns `Result<u16>` instead of `Result<u8>`.
  Explicit Rust `u8` annotations must become `u16`; inferred callers need no
  change. Workspace and CMake metadata use the 0.5.0 minor line.
- C ABI layouts, entries and version 1.5 remain unchanged. Using more than eight
  zones requires the 0.5.0 library, not merely an ABI 1.4-or-later table.
  Historical eight-zone quality/performance evidence remains scoped to its
  recorded workloads; no sixteen-zone qualification is claimed.

See [ADR 0088](../adr/0088-sixteen-zone-ocr-capacity.md).

## Rust OCR text queries

- `Session::start_ocr_text_watch` waits for a literal in one explicit region of
  a maintained session and returns an owning `OcrTextQuery`. `poll` is
  nonblocking, `wait` uses an independent caller-wait context, and `cancel` (or
  dropping the sole owner) is idempotent. A committed terminal outcome is
  immutable.
- `OcrTextWatchRequest::new` names the region and clip policy, the result
  coordinate space, the literal, a confidence in `0.0..=1.0`, a positive minimum
  analysis interval, immediate or consecutive stability, the change-detection
  policy and a query-lifetime operation context. The literal is NFC-normalized
  and edge-trimmed to 1–4,096 UTF-8 bytes. Presence is a case-sensitive substring
  within one region at or above the confidence; no case/width folding, regex,
  fuzzy matching or region concatenation is added.
- Success retains the exact frame, transform, effective region, immutable
  `OcrResult`, initialized descriptors and satisfying-region indexes. Text is
  available through explicit accessors, not `Debug`, errors or diagnostics.
- OCR and template queries share the existing limits: 256 live queries per
  engine, 64 per session, 16 sessions holding work reservations, two analysis
  workers, one latest pending frame per query, a 64 MiB/256-entry mapping cache
  and 30-second eligible queue residence. OCR occupies at most one physical
  backend lease and never creates another backend pair.
- Logical cancellation or close does not join an unreturned OCR call. That call
  keeps its frame, mapping, recognizer and lease until it returns, and logical
  close does not prove that native allocations were freed.
- The controlled public-API smoke, model-free normalization proof and
  source-bound real CPU replay ran on both targets. ADR 0075 accepts
  target-specific ceilings for the fixed CPU bounded-v2 workloads. Historical
  final enforcement recorded Apple controlled3/real5 and Windows controlled3
  passes, but Windows real process 1 measured 1.4887 ms against the 1.0 ms
  logical-close-to-physical-zero ceiling. That cohort remains `NONPASS`, and real
  processes 2–5 were not executed. Windows Graphics Capture and ScreenCaptureKit
  qualification remains open. No C or C++ OCR query surface is provided.

See the [OCR text-query guide](../ocr-text-watch.md),
[ADR 0070](../adr/0070-ocr-watch-exact-bgra-change-evidence.md) and
[ADR 0075](../adr/0075-ocr-text-watch-workload-profiles.md).

- Reuse the caller's initialized BGRA OCR model/profile/provider rather than
  restricting Rust text watching to CPU bounded-v2. Existing profile and provider
  constructors retain ownership of supported initialization.
- Require provider metadata and BGRA input; retain and recheck exact selected
  identities before analysis or change skipping. No watcher model, CPU,
  backend/version or runtime-name whitelist, default change or query fallback

- Report quality, latency and memory rules as optimization targets and caller
  information, not model-admission or development blockers. Each model may need
  its own measured configuration; no universal all-model threshold or blanket
  fastest recommendation is implied. Unmeasured target rows stay unmeasured.

  failures source-bound. Public CPU watcher smoke covers all three models with
  default and explicit CPU options; it is not native capture, accelerator or

  lifecycle violations remain defects, not performance trade-offs.

## Other source changes requiring edits

Besides the C++ wrapper retirement, these changes can require caller edits:

- `candidate_interest_membership` returns `Result<u16>` instead of `Result<u8>`.
- Constant BGR templates, including every `1x1` image, fail during OpenCV
  preparation, and originally empty regions are rejected before outward
  rounding. Neither case is a successful no-match.
- `match-report` uses `defaultPixelFormat` and `acceptedPixelFormats` instead of
  `pixelFormat`.
- Direct users of `mado-pilot-backend-onnx` must handle
  `OnnxOcrProfile::Catalog` in exhaustive matches; the facade's `OcrProfile`
  enum was already non-exhaustive.
- Direct implementers of the capture crate's `CaptureSession` trait must provide
  `commit_frame`; `StreamState::commit_frame` is the standard implementation.
  Custom providers must refuse required window geometry or resource limits that
  they cannot apply.

- Observe final macOS focus after the last retained-window inventory, then reuse
  its bounds. `System` unchanged-geometry checks use the same source frame's raw
  geometry, including backing scale; frame coordinates retain their own transform.
  Focus is a last observation, not OS-atomic delivery or application consumption.

## Template-matching measurement

The opt-in `template-matching-efficiency` Rust benchmark preserves 21 component
guards and adds 36 public Session, query and owner-lifecycle rows without capture
or input. Its collector separates baseline calibration, reviewed target profiles
and paired comparison, retaining correctness, physical work, CPU, heap and
native-memory observations. Hosted CI runs protocol-4 semantic plans for both
modes on Windows and Apple Silicon; those are not release-host qualification.
Collector reports preserve known violations alongside unavailable observations
and distinguish recorded interruptions, incomplete attempts and unstarted work.

The shared owned-process runner adds lifetime CPU records separately from
execution and cleanup outcomes, without extending deadlines. POSIX `wait4`
descendant rollup remains partial; Windows Job totals include nested jobs and
are complete only after observed zero active processes. Unavailable usage is
unknown/null, and source representation units do not establish accounting
resolution or accuracy. Windows receipts also retain that cleanup query's raw
total, active and limit-terminated process counters as `process_accounting`;
they are aggregate associations, not a process census, cap or image closure,
and older receipts do not gain them. This is apparatus, not performance
qualification.

The direct-format corpus expands the non-statistical format-transition row with
padded/full/ROI and forced-BGRA controls, persistent hits and an active production
reader spanning eviction. Its bounded owned-process smoke retains actual loaded
OpenCV paths/hashes and separate final-reader/backend checkpoints. These are
logical ownership/work observations, not full native-allocation or RSS-release
claims; each target still requires its own successful execution.

See [performance measurement](../performance.md#rust-template-matching-work-efficiency)
for build isolation, sampling and acceptance rules. Existing historical profiles
retain their original source and executable identities.

Normal release timing is separately built with `template-matching-timing`. It
excludes allocation/work accounting, reports unavailable values as `null` and
rejects feature-unified instrumentation at compile time. Normal exposes 54 rows;
instrumented exposes 57. Current executables emit only protocol 4; the collector
also reads protocol-1/2/3 wire formats. Numerical qualification is
pinned to its collector and policy revision. Logical fixtures remain separate
from each role's bound helper sources and physical-work contract. Turnover
retains hit/miss strata; query setup/close and lifecycle
ownership have explicit boundaries. This is apparatus, not a refreshed verdict.
Prepared-cache and uncached historical roles have separate validated physical
accounting, with common logical inputs/oracles. An exported measurement port
uses its own real Git commit/tree and bounded complete pre/post source checks;
the original historical artifacts retain their identities. Logical mapped
bytes, mapping copies and BGR conversion/cache ownership are not interchangeable.
Source verification preserves full Windows file identity and compares timestamps
within each metadata API. Protocol-3/4 preflight retains one complete source
identity with hash-bound boundary references inside the fixed bundle limit;
fully verified exports do not manufacture a clean checkout status.

The component protocols record the active OpenCV parallel backend and library-reported
thread setting, refusing unavailable, changed or unequal cross-role settings
without discarding workload JSON. Bounded representative macOS loader discovery
and a Windows held-file debugger preflight preserve provenance independently of
execution and cleanup. Diagnostic smoke can retain post-run identity and later
work after a fully bound row failure; Apple timing-policy collection stops
execution or semantic failures. Failed measurements never enter scalar cohorts.
Windows debugger output is not normal-timing evidence. Explicitly accepted,
source-bound method and numerical reviews, independent A/A control and
measurement-time provenance remain required; missing calibration prerequisites
cannot authorize control. [ADR 0094](../adr/0094-normal-and-instrumented-component-measurement.md)
does not accept a numerical profile or extend SDK consumer responsibilities.

The collector also supports live per-attempt checkpoints for bounded management
steps. Pauses consume the original campaign deadline; early close retains an
incomplete prefix and releases the collector lock. Ordinary CLI schedules,
sampling and grading are unchanged. This is not a persisted resume or retry
facility.

Mac component collection adds opt-in, process-bound timing markers around the

record. Historical image-only receipts remain image-only evidence. This does
not establish zero observer cost, observer-off equivalence or Windows normal
qualification; see [ADR 0095](../adr/0095-component-timed-loader-boundaries.md).

Prospective component policies also require unchanged A/A role medians to agree
within the frozen allowance and enforce the declared 15% noise cap separately
for each comparison role and turnover stratum. Per-process resource and timing
ceilings remain mandatory. Policy revisions do not regrade historical evidence
or change sampling, budgets or SDK behavior; see
[ADR 0096](../adr/0096-component-control-and-comparison-gates.md).

[ADR 0097](../adr/0097-apple-observer-on-component-campaign.md) bounds the Apple
observer-on warm component method with a native-verified management owner,
absolute stage deadlines and serialized-evidence storage admission. Calibration,
independent A/A and numerical-profile review remain required; method acceptance
is not a performance result or a Windows/consumer/release waiver.

The current normal baseline calibration is rejected by the CPU-repeatability
gate; A/A and candidate comparison remain unrun. Successful cleanup does not
establish a numerical profile or a product regression.

[ADR 0098](../adr/0098-workload-scoped-component-cohorts.md) adds protocol-3
`--workload` selection to `calibrate`, `control` and `compare`: one complete
workload per invocation, or the unchanged full corpus when omitted. For protocol-3
scopes, statistical 20/200 and contract 1/3 counts, six baseline calibration
processes, six balanced A/A pairs and six balanced comparison pairs remain
required. Case-specific lower
absolute collection clocks come only from the hash-bound method review; there is
no blanket ten-minute ceiling, universal 900-second policy or automatic
execution, aggregation or retry.

Scope and reviewed limits bind calibration, control, profile review and
comparison. Reports add `workload_coverage`; a partial `status: "passed"` does
not set `performance_qualified` or pass the whole-target timing/work verdict.
Source/observer gates, failures, per-process/resource non-regression and both
joint p95/CPU goals for selection and repeated preparation remain unchanged.
Every required case, both targets/modes and separate actual-consumer evidence
remain required for any matching performance claim; ADR 0097's historical tables
and failed calibration are not regraded.

[ADR 0100](../adr/0100-retained-loop-cpu-and-prospective-sampling.md) makes
protocol 4 the successor for new component campaigns. It keeps the protocol-3
corpus and oracles, with these changes:

- **Normal CPU:** graded by one current-process bracket over the retained loop,
  including preparation, oracles and sample storage. The summed-sample `cpu_ns`
  remains a diagnostic. Source units (`getrusage` 1 µs, `GetProcessTimes` 100 ns)
  are not accuracy.
- **Instrumented timing:** descriptive. Resource and exact work/ownership gates
  stay graded.
- **Counts:** statistical rows take counts from a frozen, hash-bound
  `--sampling-plan` within 1–1,000 warmups and 1–40,000 samples. Contract rows stay
  1/3, and smoke accepts no plan. Counts are reviewed inputs fixed before
  calibration; there is no automatic selection, resampling or retry.
- **Unchanged:** six calibrations and six A/A and comparison pairs, the noise and
  ceiling gates and both joint p95/CPU goals.

An actual Apple Silicon development smoke ran three selected rows per build mode
with zero oracle failures, valid brackets and clean process cleanup. It is not a
sampling-plan collection, whole-corpus result or qualification. Protocol-1/2/3
evidence is not regraded.

[ADR 0099](../adr/0099-actual-consumer-scalar-measurement.md) defines the prospective
actual-consumer scalar method independently of component20/200 distributions.
It selects dev-normal/observation-on, six fresh calibrations and six balanced
control/comparison pairs per case, with complete lifetime CPU non-regression,
explicit clock/resource scopes and campaign-level failure fences. It accepts no
numerical profile. Missing image, process-count, CPU/clock and resource
prerequisites continue to block numerical collection; SDK APIs, caller
responsibilities and historical outcomes are unchanged.

`tools/consumer-performance.py` provides separate source-bound consumer phases
and persistent campaign failure fences. Apple discovery retains actual root and
named-child loader records; data-only closure and source-closed accounting
evidence remain separate from method acceptance. Direct Apple trial development
smoke and trial/replay/deadline discovery contracts passed; the expected deadline
application retains `FAIL`/`Timeout` and exit 1. Windows numerical admission
remains unavailable, and no consumer profile or benefit is accepted.

## Prerequisites

Builds use the pinned Rust 1.97.1 toolchain, which is also the minimum supported
Rust version, and Python 3.13+ for `tools/setup-native.py`. Developers acquire the
native prerequisites themselves. Setup checks existing installations and
configures only the command it launches. It never downloads, installs, elevates
or changes global shell settings
([ADR 0066](../adr/0066-developer-owned-native-prerequisites.md)).

- macOS: Xcode Command Line Tools, which supply libclang, and Homebrew
  `opencv@4`. Setup selects only the dynamic `opencv_core`, `opencv_imgproc` and
  `opencv_imgcodecs` libraries
  ([ADR 0073](../adr/0073-link-only-required-apple-opencv-modules.md)).
- Windows: the official OpenCV 4.14.0 prebuilt archive, LLVM 22.1.8 and Visual
  Studio C++ build tools with a Windows SDK, run from an x64 MSVC developer
  prompt. Setup requires `--opencv-root` and `--libclang-path`.
- OCR additionally requires a caller-supplied canonical ONNX Runtime 1.29.0 file
  (`libonnxruntime.1.29.0.dylib` or `onnxruntime.dll`) and the selected profile's
  exact model resources. Explicit Windows CUDA keeps its existing qualified
  caller-provided dependency set.
- C consumers need a C compiler and CMake 3.22 or later; C++ consumers also need
  a C++ compiler. Both link `MadoPilot::C`.
- macOS capture requires an already granted Screen Recording permission, which
  MadoPilot probes without prompting. Input authorization is a separate concern.
  Windows reports integrity/UIPI outcomes without elevation.

See [CONTRIBUTING](../../CONTRIBUTING.md#native-development-prerequisites) and
[native dependencies](../third-party-dependencies.md).

## Security, privacy, and lifecycle

- Ordinary diagnostics and release evidence exclude captured pixels, recognized
  text, caller template/model identities, input payloads, credentials, raw native
  identifiers, unrelated process/window inventories and local paths. OCR query
  text is exposed only through explicit result accessors.
- `TargetProcessIdentity` paths are machine-local data. Debug output redacts them;
  keep them out of ordinary diagnostics and portable exports.
- OCR queries, capture pacing and window requirements perform no input, target
  activation, permission request or settings change. The AppKit background
  pointer mode changes pointer modifier flags and is never selected implicitly.
- Logical close, cancellation and terminal outcomes do not prove that native work
  or allocations were physically released.
- ONNX Runtime and model files load only from caller-selected canonical paths
  with their existing identity checks. Nothing is bundled, downloaded or searched
  for implicitly.

## Explicit limitations

- Template and OCR text watching are Rust-only; no C or C++ watcher or OCR-query
  entry is added. OCR predicates beyond literal presence, callbacks/subscriptions,
  automatic input, target activation, Tokio/futures integration and real-time
  guarantees are unavailable.
- Native capture, input, watcher and OCR evidence remains bound to the revisions
  and hosts stated above. The macOS 27 ASan suite does not qualify every capture
  topology or input route.
- No template-matching performance qualification, actual-consumer benefit or
  general application performance claim is made.
- Recorded numerical failures and unexecuted rows remain unchanged. These include
  the OCR query Windows real-startup `NONPASS` and the earlier Apple matching
  comparison failure.
- Optional statistical template-watch Lane C and per-model OCR rule results are
  informative; neither is a release gate.
- Packaging gates G-007 and G-012 remain open.
