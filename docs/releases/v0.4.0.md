# MadoPilot v0.4.0

MadoPilot v0.4.0 adds one bounded Rust template-presence watcher over deterministic replay/OpenCV and maintained Windows Graphics Capture (WGC) and ScreenCaptureKit sessions. A caller starts one owning `TemplateQuery`, then polls, waits under a separate operation context, or cancels it. Every terminal result is immutable and identifies its authoritative source frame.

This file is the canonical release body.

## Supported watcher boundary

The released watcher provides:

- current-once then strictly-newer frame acquisition;
- fixed finite latest-wins scheduling with observable coalescing, rejection, expiry, and overload;
- exact change/rate admission and confirmation-only stability;
- absolute monotonic deadlines and cancellation for both the query and each caller wait;
- stale-generation rejection, one immutable terminal outcome, and idempotent close;
- complete stream, epoch, sequence, and geometry-revision correlation; and
- content-redacted structured diagnostics and complete work accounting.

`crates/mado-pilot/examples/template-watch.rs` exercises deterministic replay/OpenCV. `crates/mado-pilot/examples/native-template-watch.rs` exercises qualified WGC or ScreenCaptureKit discovery, capture, matching, retained ownership, and cleanup without activating a target, injecting input, requesting permission, or printing a target title or native identifier.

## Qualification authority and release targets

ADR 0051 retains deterministic replay/OpenCV correctness and target-specific latency, RSS, live-heap, and growth profiles. ADR 0064 separately qualifies the native Rust boundary without rewriting earlier failed or apparatus-only campaigns:

- required Lane A owns deterministic scheduler, query, lifecycle, diagnostics, and complete-work semantics;
- required Windows Lane B owns the compact WGC semantic and cleanup contract;
- required macOS Lane B owns the compact ScreenCaptureKit semantic and cleanup contract; and
- optional Lane C owns statistical latency, resource, topology, and endurance evidence and does not replace a required lane.

The release targets are:

- `x86_64-pc-windows-msvc`: Windows 11 25H2 build family 26200 on a currently serviced x64 desktop installation;
- `aarch64-apple-darwin`: Apple Silicon macOS 26.5.2 or newer under the deployment contract.

Qualification V2 ran on the approved mixed-DPI Windows host and on an Apple M1 Pro running macOS 26.6.2 with SDK 26.5. Release acceptance requires repository-policy, Windows, and Apple Silicon checks on the exact final source. A result from one target never supplies authority for the other.

## Preserved v0.3.1 behavior and compatibility

The v0.4.0 product version preserves the released v0.3.1 capture, mapping, matching, input, one-shot OCR, provider, asset, diagnostic, Rust, C, and C++ behavior.

C ABI 1.5 remains unchanged. ABI 1.0, 1.2, 1.3, and 1.4 remain permanent 424-byte, 592-byte, 648-byte, and 720-byte prefixes. ABI 1.5 remains a 736-byte table whose final entries construct and describe the initialization-time OCR provider. The unreleased ABI 1.1 draft remains unsupported. The header-only C++ wrapper continues to consume only that C ABI and declares no ABI of its own.

The C and C++ watcher APIs are unavailable. Existing current and frozen-prefix C/C++ flows are compatibility regressions, not watcher APIs.

Existing OCR policy is unchanged: CPU remains the default and automatic selection on both targets; explicit Windows CUDA remains limited to its qualified boundary; CoreML remains qualification-rejected; preferred-provider fallback is initialization-only; and no inference failure switches provider.

The product version does not change the independently versioned C ABI, asset schema, replay schema, OCR model/profile identities, diagnostic schema, native watcher report schemas, or macOS shim ABI.

## Prerequisites

Builds use the pinned Rust toolchain and the target-native SDK/toolchain documented in `CONTRIBUTING.md`.

OpenCV 4 is a controlled host-provided build and runtime prerequisite. OCR additionally requires caller-supplied canonical ONNX Runtime 1.29.0 and accepted model files. Explicit Windows CUDA requires the qualified caller-provided CUDA 13, cuBLAS, cuDNN 9, NVRTC, and ONNX Runtime dependency set. MadoPilot performs no download, installation, ambient search, or privilege change.

On macOS, the hosting application must already have Screen Recording permission for capture. MadoPilot probes it without presenting permission UI or calling a permission-request API. Accessibility/event-post authorization is a separate input concern and is not required or used by a template watcher. Windows reports integrity/UIPI outcomes without elevation.

## Security, privacy, and lifecycle

Frames and results retain their native storage only for their documented ownership lifetime; retained public frames cannot consume producer slots required for capture progress. Queues and reports are bounded. A late, cancelled, stale, or superseded result cannot mutate state or trigger input. No host callback runs while an internal lock is held.

Ordinary diagnostics and release evidence exclude captured pixels, recognized text, caller template/model identities, input payloads, credentials, raw native identifiers, unrelated process/window inventories, and local paths. The watcher performs no network access, target activation, input injection, automatic action, retry, or permission request.

## Explicit limitations and migration

The watcher matches templates only. OCR predicates, wait-for-text, callbacks/subscriptions, C or C++ watcher entries, automatic input, target activation, Tokio/futures integration, and real-time guarantees are unavailable. Qualification does not claim arbitrary application, template, ROI, topology, latency, or service-level compatibility.

Existing v0.3.1 callers require no migration. Rust callers that need the watcher use `Session::start_template_watch` and retain the returned `TemplateQuery` until its terminal result is consumed or it is cancelled and closed. C and C++ callers continue to use ABI 1.5 without a watcher entry.

## Distribution scope

This source-only release publishes the permanent annotated tag, this tracked release body, and provider-generated source archives only.

Crates.io packages, prebuilt or static libraries, installers, package-manager artifacts, CMake install/export metadata, pkg-config metadata, ABI-major decorated libraries, and bundled OpenCV, ONNX Runtime, OCR models, CUDA, or cuDNN are not provided.

The CMake targets remain for development-tree consumption through `add_subdirectory`; `find_package(MadoPilot)` is unavailable. No binary attachment accompanies the provider release.
